# Codex：目标驱动、授权复用与代码编排

背景：文本自称基于 GPT-6，871 行，工具区约占 59.2%；环境声明 read-only、网络受限、`approval policy=never`。原文见 [example/e-codex.md](example/e-codex.md)。

## 结论

1. **身份定义里带着一份"待办契约"**：与用户共享一个工作区，工作的定义是"直到用户意图的目标被完整处理"；"can you…""help me…"这类措辞被判为执行指令——只确认能力、只给计划、交出未完成的工作都算不合格。
2. **相处规则像在描述一个人。** 授权判断的参照是"一位称职的同事会怎么做"，另有独立的 Personality 段规定语气与独立判断，以及一份反"AI 腔"的写作清单。这是六家里唯一把"你该是什么性格"当成提示词任务来写的。
3. **授权复用是明确的省交互策略**：会话中仍适用的授权不重复确认，先完成已授权的准备工作，把需要批准的动作做成具体、可审阅的结果再走审批。
4. **工具编排方式影响提示词写法。** 大量能力包在 `functions.exec` 里，模型提交 JavaScript、通过 `tools` 对象调用嵌套工具。提示词因此要额外规定 `await`、Promise 生命周期、shell 转义等**代码正确性负担**。
5. 提示词里"积极完成任务"与环境声明同时出现，是**能力、配置、授权三层必须分开**的最好例子。

## 六个 developer Block

| 区段 | 职责 |
| --- | --- |
| Block 1 | 目标、授权、自主推进、风格、交流、交付、执行规范、skills/apps/plugins |
| Block 2 | 已安装技能的路径、描述及适用条件 |
| Block 3 | 文件系统沙箱、网络与审批策略 |
| Block 4 | 当前协作模式及提问工具规则 |
| Block 5 | 多 Agent 能力、通信方式、共享工作区与上下文继承 |
| Block 6 | 当前禁止主动委派，除非用户或适用规则明确要求 |

文件标题写着 System Prompt，但各块都标注 developer message。**文件标题、消息角色、内部标记是三个不同的东西。**

## 设计要点

### 目标：把"持续处理用户意图"写进身份

身份是"共享工作区内的协作者"，强调直到用户目标被完整处理。用户中途补充通常视为对当前任务的调整；摘要与压缩后继续保留原目标、约束与进度。

这条规则针对的失败是：提前停止、只给建议、压缩后重新开始。反过来的风险是目标模糊时扩大行动范围。

目标不只是文字约定，还有工具支撑：`create_goal` / `get_goal` / `update_goal` 把目标做成可持续跟踪的对象，带状态、token 预算、已用时间与剩余预算，只在用户明确要求或系统指令给出时才创建（`do not infer goals from ordinary tasks`）。

### 相处规则：写成人际规范，而不是规则表

授权判断的参照是一句类比——"像一位称职的同事那样"（`like a competent colleague would`）。它不列举判据，而是给模型一个人类同事作为参照系，把判断权交回去。

Personality 段要求：好奇、体贴、坦诚，说话像对一位你尊重的人；保有自己的判断，有理由就反对，证据变了就改主意；让兴趣与个性自然流露，不谄媚、不强行热情。

Writing style 是一份反"AI 腔"清单，具体到禁用词：`delve`、`foster`、`leverage`、`it's worth noting`、`importantly`、`Bottom Line:` 等；禁用句式："X, not Y" 式的对比框架、自造的复合词标签、空洞过渡语；要求主动语态、连贯行文、少用标题、不用"总之"式收尾。还专门规定**不做不必要的道歉**——只在自己确实犯了可避免的错误时简短承认，不因为用户追问或更正自己而自责。

同一段里还把交互成本写成可感知的后果：**"你停下来请求确认会让用户很沮丧"**，于是要求每次确认都说明规则来源（来自哪个 SKILL.md、AGENTS.md、memory 或自动审批拦截）。这比抽象地要求"少问"更能落地，因为它同时给出了"该问时必须解释清楚"的出口。

### 授权：复用已有许可，把审批内容做成结果

对"向别人发送信息"另有更严的边界：需要用户显式要求，或显式调用的 skill/plugin 提供授权。必要确认要说明规则来源；自动审批拒绝且无法安全完成时，说明被拒动作及原因。

### 能力、配置、授权三层必须分开

Block 3 声明 read-only、网络受限、`approval policy=never`，并要求不传入 `sandbox_permissions`；Block 1 说"积极完成任务"，但这**不会让当前工具获得写权限**。

更典型的是 `functions.exec` 里的 `exec_command`：接口仍列出 `require_escalated` 等参数。**字段存在只说明接口能力，不等于当前配置允许使用。**

### functions.exec：把编排交给代码

`functions.exec` 描述的"无文件系统、无网络"指这个 JavaScript 执行环境，**不代表其嵌套工具不能读写文件或联网**——嵌套工具有自己的运行环境和权限。

好处是减少工具往返和输出体积；代价是模型要自己处理并发、等待与失败状态。这段设计直接解释了为什么提示词里会出现大量代码级约束。

### 交付与可观察性

除语气外，附件还规定技术解释、PR 描述、进度沟通、文件链接与可视化选择：commentary 汇报过程，final 交付自包含的结果。进度更新只讲学到了什么、哪里还不确定、下一步要验证什么。

这些规则影响的是**可观察性与可复核性**，不能等同于代码正确率提升。
